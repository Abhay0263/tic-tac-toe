  • PvP Mode: Smooth pass-and-play matches between two custom player handles.
  • Bot AI Engine: Single-player mode with instant automated Bot responses.
  • AI Move Guard: Bot never moves if the human player has already landed a winning strike or tied the game.
  • Turn Management: Clean alternating turn coordinator with real-time UI indicator.

🏆 Win & Saturation Draw Check

  • Matrix Evaluator: Scans all 8 winning combinations across rows, columns, and diagonals.
  • Automated Draw Detection: Detects tie condition when all 9 squares fill with no line.
  • Named Identity Display: Announces winner's actual username (e.g. Winner: Alice (X)!) instead of raw token strings.
  • Out-of-Bounds Protection: Rejects negative, non-integer, or >8 coordinates.

👤 Identity & Rematch Handling

  • Pre-flight Verification: /check_username endpoint inspects database records prior to game initialization.
  • Custom Confirmation Modal: Prevents new users from accidentally claiming existing players' records.
  • Seamless Rematches: Preserves verified identity flags during rematches so game boards reset without blocking.

📈 Live Leaderboard Engine

  • Multi-Dimensional Stats: Stores Wins, Losses, and Draws per username.
  • Composite Ranking: Sorted in descending order by Wins, then Draws.
  • Zero Page Reloads: Auto-refreshes leaderboard asynchronously upon match conclusion without jarring reloads.

Database Architecture & Backend Resilience

Zero-Downtime Reconnections, Schema Design & Dependency Orchestration

Relational Schema & Storage

CREATE TABLE IF NOT EXISTS players ( id INT AUTO_INCREMENT PRIMARY KEY, username VARCHAR(50) UNIQUE NOT NULL, wins INT DEFAULT 0, losses INT DEFAULT 0, draws INT DEFAULT 0, streak INT DEFAULT 0 );
  • Automatic Initialization: Mounted to /docker-entrypoint-initdb.d/init.sql for instant database bootstrapping.
  • Unique Integrity: Guarantees distinct usernames while INSERT IGNORE safely avoids match creation errors.
  • Volume Retention: Data remains completely persistent across Docker container restarts via db_data.

Reliability & Self-Healing

  • Active Connection Ping: Uses conn.ping(reconnect=True) prior to queries, eliminating MySQL timeout disconnects.
  • Pure Python Dependency Polling: wait-for-db.sh uses standard socket.create_connection, removing external dependencies like nc (netcat).
  • Lifecycle Health Checks: Backend container startup waits on db2 (condition: service_healthy).
  • Centralized Configuration: .env and .env.example provide clean separation of credentials.
